# 详细计划&执行情况

## 阶段回顾：P4 后端地基（已完成 ✅）

### 做了什么

P4 阶段主要补齐了项目之前缺的基础能力，为 P1 视频创作一体化铺路：

| 序号 | 事项 | 说明 |
|------|------|------|
| 1 | 视频封面自动截取 | 视频节点打开时自动截一帧做封面，不用每次加载整个视频，又快又省内存。截出来的封面会缓存。 |
| 2 | 视频下载缓存 | 后端加了"下载到服务器"按钮，生成的视频可以手动存到服务器本地，下次播放不用从外网重新拉。手动触发，不会自动狂下吃磁盘。 |
| 3 | 人物角色库（后端） | 新建 `characters` 表，存角色名字、描述、封面图、多角度参考图、提示词模板。后端 CRUD 接口完成。 |
| 4 | 素材上传接口 | 管理后台以前只能填链接加素材，现在可以直接上传文件，自动存到存储并创建素材记录。 |
| 5 | Docker 部署路径优化 | 加了 `ASSET_PREFIX` 环境变量，接 CDN 或 nginx 反代时设一下就能让静态资源走 CDN。 |
| 6 | AI 超分按钮修复 | 画布工具栏"AI 超分"以前点开只显示"暂未实现"，现在修好了，复用已有的高清插值放大功能（1K/2K/4K）。 |
| 7 | 用户管理（后端） | 后端用户管理接口已就位。 |

### P4 阶段总结

P4 的核心工作是"打地基"：把以后做视频和人物功能需要的底层能力（人物存储、素材上传、视频缓存、封面截取）全部补齐。这阶段没有改用户可见的功能，但 P1 可以直接调用这些能力，不用再回头补轮子。人物库前端界面、用户管理前端页面留到 P1.2 一起做。

## 阶段回顾：P1.1 图片→视频智能一条龙（已完成 ✅）

### 做了什么

P1.1 的目标是让用户在画布里完成"生图→用图做视频"的全流程，共 4 步：

| 步骤 | 内容 | 修改文件 |
|------|------|----------|
| 1 | 生图一键送入视频台 | `video/page.tsx` |
| 2 | 连线自动映射 | 已有基础（`useMemo` 实时响应连线变化） |
| 3 | 多图序列转视频 | `canvas-video-settings-popover.tsx` + `kling-v26-workbench-panel.tsx` |
| 4 | 首尾帧自动回填 | `canvas-client-page.tsx` |

**步骤 1：一键送入视频台。** 画布右键图片节点点"在视频台打开"，视频页自动把那张图加为参考图。复用了生图台已有的路由传参方式（`sourceCanvas` + `sourceNode`）。

**步骤 2：连线自动映射。** 图片节点连到视频/Config 节点后，视频设置弹窗里立刻出现该图作为首尾帧备选。核心是 `videoFrameOptionsByNodeId` 和 `videoResourceOptionsByNodeId` 两个 `useMemo` 已绑定 `connections` 依赖。唯一留到 P2 的是"通过连接端口区分普通参考图和首尾帧"，因为当前连接线没有类型字段，改动面太大。

**步骤 3：多图序列转视频。** 画布侧：连线图片一键填入 Kling V3 元素列表；工作台侧：上传的参考图一键转为元素列表 + 自动生成"第1帧/第2帧/第3帧"分镜提示词。

**步骤 4：首尾帧自动回填。** Config 节点视频生成后，若已设置首/尾帧，自动同步给连接到它的其他 Video 节点。

### 遇到的问题

- 步骤 2 的"端口区分"需改 `CanvasConnection` 类型、UI 手柄、连接逻辑三处，P1 不值得投入，已标注 P2。
- 步骤 3 画布侧自动填充只做元素列表（分镜提示词依赖文字节点）；工作台侧额外做了分镜提示词自动生成（纯文本可直接生成编号）。

### 可以改进的地方

1. 分析前先细读代码，能更快判断"已有基础"还是"需要实现"。
2. 多文件改动时拆成更小的子步骤会更清晰。
3. 每次改完代码立刻同步文档，避免积压。

### 做了什么

P1.2 的目标是让用户创建和管理角色，在画布生成图片/视频时自动带入角色的面部特征和提示词。

| 步骤 | 内容 | 状态 |
|------|------|------|
| 1 | 人物库封面上传接通 | `characters/page.tsx` — `handleSave` 先调 `uploadImage` 再保存 |

| 4 | 跨帧一致性校验 | Later |

**步骤 1：接通图片上传。** 之前 `/characters` 页面用了 `<Upload beforeUpload={() => false}>`，只持有文件引用但从不上传。修复为在 `handleSave` 中先调 `uploadImage(file)` 上传封面和参考图文件，拿回 data URL 后再 `saveCharacter`。保留了已有 URL 的兼容（编辑时不重新上传已有图片）。多个参考图用 `Promise.all` 并行上传。

**步骤 2 和 3 已有基础。** 画布角色节点类型、选择器弹窗、节点渲染、`readCharacterInputs` 读取 prompt 模板和参考图注入生成上下文 —— 这些在之前开发中已经实现，不需要额外改动。

没有阻塞性 bug，但有一个设计判断：

- 图片存储方案选择。`uploadImage` 返回 data URL（base64），存到后台数据库会让角色记录变大（尤其 9 张参考图）。考虑了上传到服务端，但当前项目以本地存储为主流方案，先用 data URL 方案上线，后续如需优化可加服务端上传。

### 可以改进的地方

1. ~~多文件上传时缺少进度显示，9 张大图上传可能需要几秒，用户只能看到按钮 loading 态。~~ **已修复**：封面上传显示"正在上传封面..."，参考图并行上传实时显示"正在上传参考图 X/9"。
2. 人物库后台模型设计很好，与参考文章中的"角色说明书"概念对齐度很高——`name/description/personalityKeywords`（身份锚点）+ `referenceUrls`（视觉锚点）+ `promptTemplate`（文本DNA），字段没有冗余。

## 阶段回顾：P1.3 流畅做视频（已完成 ✅）

### 做了什么

P1.3 的目标是让视频生成过程更可感知、可控制，视频节点功能更完善。实际做了 3 件事，第 4 件标 P2：

| 步骤 | 内容 | 修改文件 |
|------|------|----------|
| 1+2 | 任务队列面板 + 进度分阶段 | 新增 `canvas-video-task-queue.tsx` + 集成到 `canvas-client-page.tsx` |
| 3 | 视频节点连续播放 | `canvas-node.tsx` + `canvas-client-page.tsx` |
| 4 | 截取/拼接/转场 | 标 P2（需要 ffmpeg 后端） |

**步骤 1+2：任务队列面板。** 新增 `CanvasVideoTaskQueue` 组件，浮动在画布右上角，有视频任务时自动出现。展示每个任务的名称、进度条、阶段标签（排队中/生成中/下载中）、已耗时。点击任务跳转到对应节点。进度阶段根据 API 返回的 `status` 和 `progress` 字段映射中文标签。面板遵循画布主题风格，与工具栏视觉一致。

**步骤 3：连续播放。** 给视频节点 `video` 元素加了 `data-canvas-node-id` 属性，在 canvas-client-page 中全局监听 `ended` 事件，播放结束后遍历连线找到下一个 Video 节点，自动 `.play()`。实现只用了一个不到 20 行的 useEffect，没有改组件 props 链。

### 遇到的问题

- **步骤 1 的组件定位。** 最初考虑在工具栏加按钮，但工具栏已有 19 个按钮太拥挤。改为浮动在画布右上角的自动出现/收起面板，视觉干扰更小。
- **步骤 3 的跨组件通信。** 最初打算通过给 CanvasNode 加 `onVideoEnded` prop 层层传递回调。后来改用 `document.addEventListener('ended', ...)` + `dataset` 方案，免去了贯穿 3 层组件的 props 改动。

### 可以改进的地方

1. 任务面板目前没有"取消任务"功能——后端 API 不支持取消。如果后续后端接入任务取消接口，面板只需要加一个 X 按钮。
2. 连续播放目前走连线方向（fromNodeId→toNodeId），如果用户想从左到右看，连线方向需要匹配视觉流向。也许可以加一个"播放顺序"指示器。
3. 进度阶段标签依赖 API 返回的 status 字段，不同 AI 提供商返回的 status 值可能不同，后续可能需要加 provider 适配。

## 阶段回顾：P2.1 视频工作流（已完成 ✅）

### 做了什么

P2.1 的目标是把已有的创意工作流模板系统扩展到支持视频生成。

| 步骤 | 内容 | 状态 |
|------|------|------|
| 1 | 视频创作工作流模板 | `creative-workflow-workspace.tsx` — 加 `single_video` 模式 |
| 2 | 工作流变量 | 已有（text/textarea/number/select/boolean，`{{变量}}` 替换） |
| 3 | 视频结果管理 | 加 `<video>` 播放器显示、视频下载、信息标签 |

**步骤 1：视频工作流模板。** 给 `WorkflowMode` 加 `"single_video"` 值，`WorkflowGenerationConfig` 扩 11 个视频字段（模型、秒数、分辨率、音频开关等）。编辑器根据模式切换：视频模式→`ModelPicker capability="video"` + `VideoSettingsPanel`；图片模式不变。新建视频工作流预填场景/运动/氛围三个变量。

**步骤 3：视频结果展示。** 之前视频生成结果被套用 `<Image>` 组件渲染（显示裂图）。修复为根据 `mimeType` 分叉：`video/mp4`→`<video controls>`，其余→`<Image>`。同时修复下载后缀（`.mp4` vs `.png`）和信息标签（显示秒数而非张数）。

### 遇到的问题

- **类型 Pick 的局限性。** `WorkflowGenerationConfig` 通过 `Pick<AiConfig, ...>` 从全局配置类型选取字段。加视频字段时需同步加 11 个 key，遗漏一个就存不下。不是大问题但手写容易出错。
- **视频结果和图片结果混存。** `WorkflowRunResult` 只有 `imageUrl` 字段没有单独的 `videoUrl`，视频 URL 也走 `imageUrl`。通过 `mimeType` 区分渲染方式，能跑但不够干净。如果未来有更多媒体类型，建议拆成 union type。
- **`VideoSettingsPanel` 的 config 对象不对齐。** 面板接收 `AiConfig` 但工作流用的是 `WorkflowGenerationConfig`，需要通过 `as unknown as AiConfig` 强制转换。运行时没问题（字段名一致），但类型安全缺失。

### 可以改进的地方

1. `WorkflowRunResult` 拆成 `WorkflowImageResult | WorkflowVideoResult`，各自有正确的字段。
2. 视频生成应像图片一样写入历史日志（localforage + 服务端 sync），目前只存了内存状态。
3. `VideoSettingsPanel` 的 config bridge 可以用 adapter 函数代替 `as unknown`。

## 阶段回顾：P3.1 视频工作区重构（已完成 ✅）

### 做了什么

P3.1 的目标是升级视频工作台的布局——全屏沉浸式、时间轴分镜浏览、分镜一站式编辑。

| 步骤 | 内容 | 修改文件 |
|------|------|----------|
| 1 | 视频台全屏模式 | `video/page.tsx` + `kling-v26-workbench-panel.tsx` |
| 2+3 | 时间轴+分镜编辑器 | 新增 `kling-storyboard-panel.tsx` + 集成到 workbench |

**步骤 1：全屏模式。** 扩展 `WorkbenchLayout` 加 `"fullscreen"` 选项。全屏时用一个 `fixed inset-0 z-[140]` overlay 覆盖整个视口，只渲染工作台面板，隐藏 nav/结果面板。WorkshopHeader 和 KlingHeader 各加一个"全屏"按钮，点"退出全屏"回到 side 模式。layout 状态存 localStorage，刷新不丢。

**步骤 2+3：时间轴+分镜编辑器。** 新建 `KlingStoryboardPanel` 组件。上方是可拖拽排序的水平时间轴——每张卡片显示帧号、时长标签、提示词预览（2 行截断），选中的卡片蓝色高亮。下方是选中分镜的编辑区——时长数字输入 + 提示词 textarea。取代了之前每个分镜独立展开一个 KlingSection 的分散布局。拖拽排序用已有的 dnd-kit，零新增依赖。

### 遇到的问题

- **图标兼容。** 一开始用了 `Maximize`，但项目 lucide-react 版本没有这个图标（有 `Maximize2`）。已统一改为 `Maximize2`。
- **分镜编辑器的数据流设计。** 考虑过把元素列表也合并进分镜（每段分镜带自己的参考图），但发现 Kling API 中 `multi_prompt` 和 `element_list` 是独立字段，强行合并会造成数据不兼容。最终时间轴只展示 multi_prompt 序列，元素列表保持独立面板。
- **selectedIndex 越界。** 排序后索引需要 clamp 到新长度，否则选中状态指向不存在的分镜。

### 可以改进的地方

1. ~~全屏时按 Esc 退出全屏~~ **已实现**（视频页 Esc 退出全屏，画布页 Esc 取消选中）。
2. 时间轴卡片可自定义宽度（按 duration 比例缩放，视觉上更接近真实时间轴）。
3. 分镜编辑器可加"从剪贴板读取"和"清空"按钮（与旧 UI 的 pastePrompt/clear 功能对齐）。
